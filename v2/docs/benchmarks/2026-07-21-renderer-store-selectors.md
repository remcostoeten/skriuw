# Renderer store selector observations

Date: 2026-07-21

## Objective

This spike asks whether React can preserve Skriuw's render invariants over normalized 1,000-node and 5,000-node renderer state without a broad mutable context or a state-library dependency. The target is narrow selector delivery, a persistent editor host, bounded tree DOM, editor-owned typing, and synchronous memory-only navigation.

It does not select React or a final store, implement the product shell, change either editor adapter, close bounded-editor correctness, measure a desktop bridge, or justify ADR-0020.

## Architecture

`spikes/renderer-store` contains a dependency-free normalized store plus a React adapter built on `useSyncExternalStore`. React and React DOM are spike-only dependencies.

The state contains stable node records, parent-to-child ID arrays, canonical node order, a cached visible-ID projection, expansion and disabled sets, active note, independent tree focus, stable prepared-document identities, note metadata, and one unrelated settings selection. Editor text, composition, transient selection, and typing never enter the renderer store.

`update` returns the original state for domain-equivalent work. Effective updates snapshot subscriber registrations, evaluate selectors, apply equality, update the selected cache before delivery, isolate failures, and queue reentrant updates FIFO. New subscriptions do not see the current delivery pass; an immediate unsubscribe prevents a not-yet-visited callback. Complete teardown marks and removes every registration.

The React binding caches the last equivalent selector result so `getSnapshot` is referentially stable. No context carries a workspace snapshot.

## Component ownership

| Component | Subscription | Ownership |
| --- | --- | --- |
| `ApplicationShell` | none | Static chrome, fixture controls, benchmark ledger |
| `TreeHost` | `visibleIds` only | Fixed 28 px virtual window, scroll position, keyboard handler |
| `TreeRow` | own active/focus/expanded/disabled tuple | One mounted row's visual state |
| `EditorHost` | none | Persistent host sentinel and editor-owned surface |
| `EditorSelectionConsumer` | active prepared-document reference | Installs selected prepared identity without host remount |
| Metadata field consumers | one scalar field each | Title, word count, or updated timestamp |
| `SettingsConsumer` | unrelated settings scalar | Isolation control |

The tree uses 8-row overscan and a computed 36-row ceiling at the measured 532 px viewport. The previous vanilla candidate's 40-row ceiling remains the repository's looser comparison point.

## Build and measurement method

Fixture fetch, JSON parsing, normalized indexing, document/metadata preparation, initial flattening, code loading, and initial React mount complete before `window.__SKRIUW_RENDERER_STORE__` is exposed.

Two separate production artifacts avoid mixing profiling overhead into ordinary latency:

- Ordinary production wraps each action in `flushSync` and records store dispatch, selector delivery, the resulting React commit, and a forced layout read inside one settled sample. Next-frame gaps, raw samples, selector notifications, diagnostic render invocations, Long Tasks, Long Animation Frames, DOM, and lifecycle state remain separate fields.
- Production profiling aliases `react-dom/client` to `react-dom/profiling`. React Profiler groups commits by commit time. Function-body counters are diagnostic render invocations, not purity-compliant application instrumentation and not committed-render proof.

Each scenario awaits a frame between samples so commits settle independently:

- 100 direct selection diagnostics over top, middle, and bottom notes.
- 100 direct active-note changes in reverse order, including visible and offscreen rows.
- 40 shallow/deep folder toggles where folders exist.
- 30 editor-owned input updates.
- 30 metadata-title updates.
- 100 equivalent store updates.
- 100 selector-subscription setups and 100 separate teardowns with raw timing samples.

The automation then arms trusted input, focuses the native tree, and prepares 34 top, 33 middle, and 33 bottom consecutive-note anchors outside each key timing. It sends exactly 100 ArrowDown key pairs through CDP at 24 ms spacing, asserts 100 active-note transitions, and captures exactly 100 uncensored trace `EventDispatch` durations. Capture-phase timing starts before the React handler. Event Timing uses its 16 ms reporting threshold. Its missing entries remain censored and are not passes. Frame callbacks are pre-paint. Trusted Long Task and Long Animation Frame observers stay active for the full native capture; their browser thresholds still cannot prove the 8 ms contract.

## Render and notification invariants

A representative visible nested selection produced one commit with these diagnostic invocations; Profiler boundaries inside the memoized row components independently reported the same previous row, next row, editor-selection, title, and word-count consumers:

| Consumer | Invocations |
| --- | ---: |
| Previous visible row | 1 |
| Next visible row | 1 |
| `EditorSelectionConsumer` | 1 |
| `MetadataTitle` | 1 |
| `MetadataWordCount` | 1 |
| Application shell | 0 |
| Tree host | 0 |
| Persistent editor host | 0 |
| Metadata panel | 0 |
| Unrelated settings consumer | 0 |
| Offscreen rows | 0 |

The unchanged updated-at value correctly did not render merely because the active identity changed. Updating only the title rendered `MetadataTitle` once per effective update and no other component.

Across 100 direct selection diagnostics, 99 were effective because the first selected identity already matched. Each effective offscreen selection notified the editor selection, title, and word-count selectors; mounted previous/next rows added up to two notifications only when applicable. No shell, tree-host, editor-host, metadata-panel, settings, or offscreen-row render occurred from selection. The native path separately proved 100 trusted active-note transitions over top, middle, and bottom anchors.

Expansion rendered `TreeHost`, the toggled visible row when mounted, and rows entering the virtual window. Existing unrelated rows, editor selection, metadata, shell, editor host, and settings stayed unchanged. Collapsing an active note's ancestor preserved `activeNoteId`, moved only tree focus to the collapsed folder, and restored selected styling after re-expansion.

Thirty editor-owned inputs produced zero selector evaluations, notifications, React commits, or React render invocations. One hundred equivalent updates produced zero selector evaluations, notifications, commits, or renders. One hundred measured subscription setups followed by 100 measured teardowns returned to the exact baseline listener count.

## Correctness assertions

Seven deterministic store tests pass:

- canonical order and hidden active selection survive collapse/re-expansion;
- equivalent updates and selector-equivalent unrelated changes are silent;
- unsubscribe is idempotent, prevents later notification, and disabled notes cannot become active;
- notification-time unsubscribe/add and reentrant FIFO updates are deterministic;
- subscriber failure preserves state and listener bookkeeping;
- destroy removes every listener and rejects later work;
- initial active-note fallback skips disabled documents.

Every browser context additionally passed visible-selection isolation, equivalent-state silence, expansion isolation, editor-owned typing, bounded rows, meaningful content, active/disabled/reduced-motion state availability, lifecycle guards, exact trusted-key counts, zero console errors, zero page exceptions, and zero subscriber leak.

## Budget result

All measured ordinary-production interaction-work P95 values were below 8 ms and every maximum was below 16.67 ms. The largest clean observation was 12.165 ms during mixed-5000 expansion. Five earlier fresh nested-5000 selection runs stayed at 1.32–2.25 ms P95 with maxima of 1.64–3.54 ms. Exact per-scenario allowlists, function-invocation diagnostics, Profiler boundaries inside memoized leaf consumers, and root commit counts agreed in the final profiling replay.

This is a viable renderer-store candidate for later ADR-0020 consideration. It is not a universal performance pass: there is no fixed runner, the raw artifacts and full traces are not committed, Event Timing is censored, requestAnimationFrame is pre-paint, and trace dispatch does not include final presentation.

## Raw evidence and limitations

Raw JSON, CDP trace summaries, and screenshots are preserved locally under ignored `spikes/renderer-store/results/` with `final-production-clean-*`, `final-profiling-*`, and `verified-repeat-*` names. Because those artifacts are not committed, all timing conclusions remain exploratory. A deliberately concurrent correctness replay was excluded from latency reporting because two simultaneous Chrome suites materially distorted the mixed expansion samples.

The spike uses prepared identity sentinels, not a real editor state installation. Body-level render counters are diagnostic-only; leaf and root React Profilers own committed-render evidence. `flushSync` is a conservative measurement boundary inside the disposable harness, not a product architecture recommendation. Browser console/page failures, render-allowlist violations, partial traces, incorrect trusted transition counts, and lifecycle leaks fail the command, but this is not a full accessibility audit. No memory ceiling was recorded because normalized maps, 5,000 small prepared identities, and a bounded row pool were not the dominant unresolved product risk.

Bounded-editor window movement, scroll anchoring, canonical edit reconciliation, selection/focus restoration, clipboard/find/IME/undo/accessibility semantics, representative plugins, desktop bridge overhead, and fixed-runner presentation evidence still precede ADR-0020 and product UI scaffolding.
