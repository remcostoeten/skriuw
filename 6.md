## Concrete deliverables

### 1. Worker-owned database lifecycle

Open/create exactly one workspace database inside a dedicated worker. Apply the
same ordered SQL migrations and immutable checksum checks as native SQLite.
Define readiness, close, flush, reopen, version-too-new, migration failure,
storage-denied, quota, corruption, unsupported-browser, and worker-crash
behavior.

All SQLite and OPFS work stays off the renderer thread. Do not expose the
database handle or filesystem primitives across the worker boundary.

### 2. Typed browser bridge

Implement versioned request/response messages for the narrow storage use cases.
Use generated/shared contracts where available, validate every trust boundary,
bound request IDs and payloads, correlate exactly one terminal response, and
project stable actionable errors. Cancellation or worker restart must not leave
promises unresolved indefinitely.

Keep renderer/store APIs adapter-neutral. Do not add runtime-specific branches
to product rules or broad React context.

### 3. Storage behavior parity

Implement canonical mutations, transactions/savepoints, search projections,
settings/app state, archive import/export, and relevant sync operational tables
using shared migrations and domain validation. Choose and document browser
history behavior; do not pretend native Git history exists in the browser.

Portable archives are the minimum recovery boundary. Import must validate
fully and replace atomically; export must contain canonical portable content,
not OPFS internals or operational queues.

### 4. Offline durability and recovery

Prove fresh boot, edit, refresh, browser restart, offline operation, export,
import, migration, worker restart, and interrupted write behavior. Define what
happens when persistence is unavailable or quota is exhausted. Never silently
fall back to ephemeral storage for a workspace presented as durable.

### 5. Native/browser parity and performance

Run the same operation, snapshot, archive, validation, and migration fixtures
against native and browser adapters. Add browser integration/E2E coverage for
worker readiness, editing, refresh, offline mode, and errors.

Measure startup and representative 1,000/5,000-note plus editor cases against
`v2/docs/performance-contract.md`. Navigation after startup must use cached local
state and must not await worker, OPFS, parsing, lazy loading, or network work.

## Non-goals

- No IndexedDB/in-memory substitute presented as the requested OPFS runtime.
- No raw SQLite replication to cloud.
- No account UI or public cloud sync unless separately authorized and complete.
- No speculative generic storage abstraction.
- No deploy, commit, or push.

## Done condition

A supported browser creates and reopens an OPFS-backed workspace, performs the
relevant public storage operations offline, survives refresh/restart without
loss, exports/imports a validated archive, passes native/browser fixtures, and
meets measured interaction budgets. Unsupported or failed durable storage is
explicit and recovery-oriented, never silent.
