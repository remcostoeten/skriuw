Problem: Prisma-specific JSON, error codes, transactions, and generated types leak across eighteen web domain modules.

Solution: define seams around persistence capabilities required by each command; keep ORM mapping and error translation in adapters.

  • • Drizzle change stays local
  • • ORM errors become domain errors
  • • atomicity remains explicit
One adapter is hypothetical. Add a seam first where Prisma and SQLite already vary, or where a tested Drizzle migration is genuinely planned.

Problem: generic CRUD filenames classify code by database verb, while real reads differ by screen, runtime, indexing, and performance.

Solution: separate commands from queries, but let each query return its required projection and use the best adapter implementation.

  • • no lowest-common query DSL
  • • reads remain optimizable
  • • write rules stay protected
