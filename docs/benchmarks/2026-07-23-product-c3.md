## Product workflow

The production renderer passed 13 grouped keyboard-driven scenarios and 37
assertions from a fresh browser profile. The scenarios cover create, rename,
sibling reorder, nesting, cross-folder context-menu movement, writing, slash
commands, find/replace, sidebar search, trash/restore/purge, metadata and
history restore, the command palette, shortcut rebinding, settings, archive
export/import, backup, and recovery.

The run also proves the initial active and empty-trash states, active
selection, disabled actions, an injected archive-export error, reduced-motion
application, settings focus restoration, and the complete grouped scenario
set. Browser console errors and page errors were empty. A second clean-profile
run passed the same 37 assertions before the harness was committed.

The native bridge is deterministic in this workflow gate, but the renderer,
store, editor, shell, command paths, and mutation reconciliation are the
production implementations. Native archive, backup, recovery, runtime
shutdown, and accepted-operation draining remain covered by the Rust and Tauri
regression suites.

All 300 trusted keyboard switches completed. Every fixture passed the cached
editor-swap, selection-dispatch, keystroke-to-paint, and zero-dropped-frame
budgets. Navigation produced no bridge calls or resource loads, mounted one
editor host and one ProseMirror view with zero remounts, and recorded no long
tasks or Long Animation Frames. Typing produced zero React commits. All
deterministic correctness assertions passed.

The raw selection mark includes selected-consumer installation after dispatch
and recorded isolated maxima above 8 ms. The Chrome trace is the main-thread
navigation-task authority for that separate contract; its maximum remained
below 8 ms in every fixture. The 500-block editor maximum was 16.2 ms, leaving
0.47 ms of headroom below the 16.67 ms ceiling.

## Builds and visual verification

`./scripts/build.sh web` passed and produced the renderer bundle.
`./scripts/build.sh desktop` passed and produced the optimized 15 MiB Linux
Tauri binary. Each entrypoint reran generated-contract checks, formatting,
Clippy, 114 backend tests with 6 ignored, 17 desktop tests, 9 UI-architecture
tests, 7 renderer-store tests, 119 renderer tests, coverage, and type safety.

The production performance page was reviewed at 1,280 × 720. It presented the
dense shell, bounded tree, editor, and metadata surface without a Vite overlay,
console error, or page error.

## Claim and limitations

This evidence closes C3 for the named Linux reference machine. Linux is the
only v1 platform claim. Windows and macOS require the identical workflow,
performance, native bridge, build, and visual suite with committed evidence.

The timing host was a normal desktop rather than a dedicated CI appliance;
several discarded exploratory runs showed scheduler variance while other
desktop applications were active. The committed run is the complete passing
run, and the raw file retains every sample. Chrome provides the reproducible
production-renderer timing trace. Native Linux WebKit is covered by the
optimized build and focused Tauri regressions, but the complete workflow was
not driven through WebKit automation. Crash, SIGTERM, and platform application
menu quit behavior remain outside renderer close-boundary proof.
