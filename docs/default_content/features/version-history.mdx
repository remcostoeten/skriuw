# Version History

Skiruw quietly saves checkpoints of your notes as you work, so you can look back at how a note evolved — or undo a change you regret — without any extra effort.

## How it works

As you type, Skiruw saves your progress in the background. It's smart about when to create a new checkpoint: small typo fixes and whitespace tweaks are skipped, and a burst of typing within the same short window is grouped into a single checkpoint instead of dozens. The result is a clean, meaningful timeline instead of noise. Renaming a note, creating it, and restoring an old version all get their own checkpoint too, so those moments are always easy to find.

## What you can do

- **Browse the timeline** — open a note's history to see a graph of checkpoints, newest first, each with a short preview of what changed
- **See the difference** — every checkpoint shows how many words and characters were added or removed compared to the version before it
- **Restore any checkpoint** — jump back to an older version of a note in one click
- **Track restores** — restoring a checkpoint creates a visible fork in the timeline, so you can see exactly when and from where a note was rolled back
- **Keep a long memory** — Skiruw keeps a generous history of checkpoints per note, so you rarely have to worry about older versions disappearing

## Tips

- Use version history to recover a paragraph you deleted by accident, or to see what a note looked like before a big rewrite
- The word/character delta next to each checkpoint makes it easy to spot the moment a note grew or shrank significantly
- Restoring doesn't erase anything — it adds a new checkpoint on top, so you can always go back again

## Why use version history?

Notes change over time, and not every change is an improvement. Version history gives you a safety net: write freely, experiment, delete whole sections — knowing that every meaningful past state of your note is still there if you need it back.
