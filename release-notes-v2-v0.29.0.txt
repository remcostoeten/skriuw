## What's new in 0.29.0

This release focuses on durability and reliability: your work survives more failure modes, and the failures that remain are visible instead of silent.

### Your drafts don't disappear anymore
- If saving fails while you're editing — in either the rich-text or raw Markdown editor — the failure is now shown with a retry option instead of being silently dropped. The save-recovery model is documented so the behavior is predictable.
- Closing the window while a save fails no longer discards your draft: the window stays open and the save is retried on the next close attempt.

### Sturdier under load
- Documents are now validated for shape, size, depth, and operation-group size at every layer (domain, runtime, and SQLite), with shared limits so nothing slips through a gap between layers.
- A new working-set LRU cache bounds how much editor state lives in memory, keeping large workspaces responsive. Working-set behavior and startup preparation are now instrumented in the performance harness.
- Archive imports are significantly faster: quadratic scans were eliminated and full-text search entries are now inserted directly.

### Reliability fixes
- A history materialization failure on one note no longer blocks later revisions, and deferred history retries can be re-claimed. History drain work is now batched with yields between bounded batches, and batch boundaries are covered by tests.
- Uploading the same image concurrently now produces a single verified blob instead of risking corrupted content.
- Debounced persistence (pane layout, sidebar expansion) now supports explicit flush/dispose with proper failure propagation.

### Portability
- The domain and storage crates now build for `wasm32-unknown-unknown`, enforced by a dedicated CI gate — keeping the core free of OS and backend dependencies.

### Documentation
- The v2 architecture docs now include accessible embedded diagrams.
