## Objective

Expose the existing v2 sync push and pull capabilities only through a
production-shaped authentication and workspace-authorization boundary.

An authenticated identity must be resolved from trusted credentials, then
authorized as a member of the requested workspace before the Worker invokes its
`WorkspaceSyncObject`. Caller-supplied user, device, or workspace identifiers
must never substitute for authorization.

## Concrete deliverables

### 1. Trusted identity boundary

Add the smallest provider-specific adapter that validates credentials and
returns a typed identity. Define stable error codes for missing, invalid,
expired, and revoked credentials. Never log tokens, cookies, note content, or
raw provider responses.

### 2. Workspace authorization

Authorize the trusted identity against a server-owned membership source before
resolving a Durable Object. Define explicit roles and the push/pull permissions
each role receives. Reject nonexistent workspaces and non-members without
leaking private workspace metadata.

Device IDs remain protocol identifiers, not authentication credentials. Bind
or validate devices under the authenticated membership where necessary.

### 3. Public route integration

Add bounded versioned push and pull routes that:

- authenticate first and authorize second;
- validate path, body, protocol version, identifiers, sizes, and operation
  fields at the Worker trust boundary;
- derive the Durable Object target only after authorization;
- map failures to stable safe response codes;
- preserve the existing ordered, idempotent log semantics;
- leave `/health` free of private information.

Do not enable routes unless real production-shaped authentication and
authorization are both configured and tested. Fail closed when configuration is
missing.

### 4. Security and revocation behavior

Specify session expiry, clock tolerance, membership removal, workspace deletion,
and credential revocation behavior. A previously valid session must stop
obtaining new sync data after revocation. Do not let caches extend authorization
past an explicitly documented safe bound.

### 5. Tests and documentation

Test public Worker interfaces for:

- missing, malformed, expired, and revoked credentials;
- member and non-member push/pull;
- cross-workspace and guessed-ID access;
- role restrictions and removed membership;
- malformed envelopes and operation-policy rejection;
- duplicate retries, conflicting duplicates, sequence gaps, bounded pull, and
  workspace isolation;
- absent/misconfigured secrets failing closed;
- response and log output not exposing credentials or workspace content.

Document local setup, secret names without values, provider configuration,
membership ownership, error codes, and key rotation/revocation. Update the
master tracker only for behavior proven by code and tests.

## Done condition

An authenticated authorized member can push and pull only their permitted
workspace through the versioned Worker API. Every unauthenticated,
unauthorized, revoked, cross-workspace, and misconfigured case fails closed in
tests. If a real provider decision is missing, public routes remain disabled
and the handoff must name that exact blocker.
