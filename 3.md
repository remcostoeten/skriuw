## Objective

Connect the native SQLite sync queues to the authenticated v2 Worker API using
a cancellable background coordinator. Prove that two desktop databases can
exchange operations after offline edits and restarts without putting network,
filesystem, parsing, or sync waits on typing or navigation paths.

## Concrete deliverables

### 1. Narrow transport contract

Define a concrete push/pull transport around generated v2 contracts. Classify
authentication, authorization, validation, conflict, rate-limit, transient
network, server, cancellation, and protocol-version failures. Bound request
sizes, response sizes, batches, timeouts, and retries. Do not add a generic HTTP
framework abstraction.

### 2. Background coordinator

Implement a single owner for sync lifecycle and durable queue interaction. It
must:

- claim and push outbound batches without holding SQLite transactions during
  network work;
- acknowledge only exact accepted batches and safely release retryable leases;
- pull from the durable observed cursor and apply ordered envelopes using the
  existing storage port;
- react safely to cancellation, shutdown, logout, session refresh, offline
  transitions, and process restart;
- use bounded exponential backoff with jitter and server retry hints;
- never create duplicate concurrent push or pull loops for one workspace.

Trigger background work after relevant local commits and on startup, reconnect,
focus, manual refresh, and bounded polling. Coalesce triggers instead of
creating unbounded tasks.

### 3. Runtime and UI boundary

Expose a narrow status projection: local-only, connecting, up to date, pending,
offline, authentication required, conflict, retrying, or blocked. UI reads this
projection and may request connect, disconnect, retry, or refresh; it must not
own retry or cursor logic.

Keep local startup available without account or network. Logging out pauses
sync and preserves the local database and pending work. An existing workspace
becomes connected only through a separately specified explicit upload/connect
flow; do not silently attach it to an empty or existing cloud workspace.

### 4. Deterministic two-device harness

Create a fake clock and fake authenticated transport capable of delays,
duplicates, gaps, retries, expiry, disconnects, and reordered responses. Prove:

- local-only mode performs no network calls;
- local edits commit while offline and upload after restart/reconnect;
- acknowledgement loss retries the same operation identity;
- pull duplicates and local echoes never reapply content;
- cursor gaps and malformed responses do not advance the cursor;
- semantic conflicts remain durable and visible while later operations proceed;
- expired sessions pause safely and resume after refresh;
- shutdown cancels work without losing durable queue state;
- two databases exchange supported non-conflicting operations.

Do not claim full convergence until the merge matrix prompt is complete.

### 5. Performance evidence and documentation

Instrument tests to prove no transport begins on navigation, search, export, or
recovery paths. Measure representative connected and local-only editing and
navigation behavior against `v2/docs/performance-contract.md`. Document trigger,
retry, cancellation, logout, and status semantics.
